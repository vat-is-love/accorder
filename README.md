# Accorder

Редактор текстов песен с аккордами. Веб-версия работает без Node.js: библиотека и текущие TXT сохраняются в IndexedDB браузера. Локальный файловый режим с Node.js 20+ также сохранён. У приложения нет внешних зависимостей во время работы и нет этапа сборки.

## Веб-версия без Node.js

Папка `dist/` содержит готовый статический сайт, включая `index.html`, `app.js`, `core.js`, `storage.js`, `archive.js` и `style.css`. Его можно разместить на GitHub Pages; запускать `server.mjs` для сайта не нужно. Простое открытие `index.html` через `file://` не поддерживается: нужны HTTPS-хостинг или локальная раздача статических файлов.

В веб-режиме «Сохранить» и Ctrl/Cmd+S записывают все поля песни и её актуальный TXT в IndexedDB одной транзакцией. При повторном сохранении обновляется та же песня и тот же TXT; история версий не создаётся. Библиотека открывается из браузера при следующем посещении. Автосохранения нет. Если IndexedDB недоступна или запись не удалась, показывается ошибка; несохранённые изменения остаются в редакторе.

Песни принадлежат браузерному профилю и адресу сайта; они не отправляются на GitHub и не синхронизируются между компьютерами. Имя базы также учитывает путь сайта, чтобы разные копии accorder в разных репозиториях не смешивали библиотеки. Очистка данных сайта, приватный режим или удаление браузером хранилища могут привести к потере библиотеки. Для резервных копий используйте JSON.

- «Экспорт JSON» скачивает **сохранённую библиотеку** целиком в `accorder-library.json`. Несохранённые правки редактора в копию не входят.
- «Импорт JSON» принимает эту резервную копию, массив песен или отдельные JSON-файлы из старой папки `songs/`. Можно выбрать несколько файлов; общий лимит — 10 МиБ за один импорт, для каждой песни — 1 МиБ. Сначала проверяются все данные, затем вся пачка записывается одной транзакцией. Замена существующих идентификаторов требует подтверждения. Старые песни без автора и примечаний поддерживаются.
- «Все TXT» скачивает ZIP с папкой `exports/` и актуальными TXT всех сохранённых песен. Названия файлов — названия песен; совпадения получают числовой суффикс. Внутри IndexedDB хранится один TXT на песню.
- «Экспорт TXT» в редакторе скачивает текущую открытую песню, включая автора и примечания.

Автоматической записи в настоящие папки `songs/` и `exports/` в веб-версии нет: файловая библиотека остаётся в локальном режиме, а веб-версия предлагает JSON и ZIP для скачивания. Существующие локальные песни автоматически в браузер не переносятся: выберите их JSON через «Импорт JSON» на опубликованном сайте.

## Публикация на GitHub Pages

Публикацию выполняет владелец аккаунта. В репозиторий нужны код и документация; личные `songs/`, `exports/`, `node_modules/` и `release/` загружать не нужно. Они исключены из подготовленного архива и перечислены в `.gitignore`. Для настоящего open source отдельно выберите лицензию: один публичный репозиторий её не заменяет.

1. На GitHub создайте публичный репозиторий `accorder` с основной веткой `main`. Для нового пустого репозитория можно сразу выбрать загрузку существующих файлов.
2. Распакуйте подготовленный `release/accorder-github.zip` на компьютере. Через **Add file → Upload files** загрузите содержимое архива: папки `dist/`, `test/` и остальные файлы проекта. Загружать нужно содержимое, а не сам ZIP и не дополнительную внешнюю папку. Сохраните изменения в `main`.
3. Убедитесь, что в репозитории есть `.github/workflows/pages.yml`. Если скрытая папка `.github` не загрузилась, выберите **Add file → Create new file**, введите полное имя `.github/workflows/pages.yml`, скопируйте содержимое [готового workflow](.github/workflows/pages.yml) и сохраните в `main`.
4. В **Settings → Pages → Build and deployment → Source** выберите **GitHub Actions**.
5. Откройте **Actions → Publish accorder → Run workflow**, выберите `main` и запустите публикацию. Первый автоматический запуск до включения Pages мог завершиться ошибкой; после шага 4 запустите его заново.
6. После успешного выполнения откройте ссылку в **Settings → Pages** или в результате задания `deploy`. Для репозитория `accorder` она обычно имеет вид `https://ИМЯ.github.io/accorder/`.
7. Проверьте создание, сохранение и повторное открытие песни после обновления страницы; затем импортируйте свои JSON. При следующих изменениях файлов в `main` сайт обновится автоматически.

Workflow публикует только `dist/`, без сервера, тестовых зависимостей и личных файлов. Пути ресурсов относительные и работают в подпапке репозитория. Сайт остаётся доступным по одному адресу, чтобы не менять привязку браузерной библиотеки. Инструкция опирается на [документацию GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## Локальный файловый режим с Node.js

В каталоге проекта выполните:

```sh
node server.mjs
```

Также доступен `npm start`. Откройте [http://127.0.0.1:3210](http://127.0.0.1:3210). Сервер слушает только этот компьютер. Для другого порта используйте `PORT=3211 node server.mjs`.

Обычный Node.js — штатный способ запуска. Если он отсутствует в PATH, в текущем окружении доступен запасной путь:

```sh
cd /home/ekkore/wrk/accorder
/home/ekkore/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node server.mjs
```

Это встроенная среда выполнения Codex, а не отдельно установленная для проекта версия Node.js. Этот путь зависит от текущего компьютера и не является требованием проекта.

## Реализованные возможности

### Песни и библиотека

- «Новая песня» создаёт пустой редактор с названием, автором и исходным текстом. Название обязательно для сохранения, максимум 200 символов. Необязательное поле автора расположено под названием, максимум 200 символов в одну строку.
- Библиотека показывает сохранённые песни, их количество и даты изменения; последние изменённые идут первыми. Нажатие на песню повторно открывает её текст и аккорды из файла.
- В файловом режиме «Сохранить» или Ctrl/Cmd+S явно записывает песню в `songs/<UUID>.json`. Первое сохранение создаёт файл, последующие обновляют его. Одновременно в `exports/<название песни>.txt` записывается текущий TXT песни: один файл на песню, обновляемый при каждом сохранении, при переименовании прежний TXT удаляется. Недопустимые для имени файла символы заменяются; при совпадении названий добавляется номер: `Песня (2).txt`. Уже существующие песни попадают в `exports/` при следующем сохранении. Автосохранения нет.
- Строка состояния сообщает о несохранённых изменениях, сохранении и ошибках. При создании/открытии другой песни с несохранёнными изменениями запрашивается подтверждение; при уходе со страницы используется предупреждение браузера.

### Текст и расстановка аккордов

Введите или вставьте исходный текст и нажмите «Применить текст». Панель исходного текста можно свернуть и открыть снова. До применения прежняя разметка остаётся на экране; сохранение и TXT-экспорт изменённого, но неприменённого текста заблокированы.

Позиции аккордов находятся над русскими гласными (включая «ё») и латинскими `a e i o u y`, без учёта регистра, а также перед началом и после конца каждой непустой строки. Пустые строки между куплетами сохраняются.

Нажатие на позицию открывает настоящее поле ввода прямо на месте аккорда. При наборе ширина поля и раскладка обновляются без пересоздания ввода и потери каретки. Видимая строка сохраняет положение прокрутки; для невидимой позиции выполняется минимальная прокрутка до поля и соответствующего текста.

Обозначения произвольные, до 40 символов, без внутренних пробелов и управляющих символов, например `Cmaj7/G`. Пробелы по краям при фиксации обрезаются. Подсказки из встроенного словаря показывают до 10 вариантов по началу введённого обозначения без учёта регистра. Вариант можно выбрать мышью или стрелками; выбор мышью принимает его и оставляет поле открытым. Отдельной панели с кнопками «Удалить» и «Готово» нет.

### Примечания

Необязательное многострочное поле «Примечания» находится после панели исходного текста и перед разметкой аккордов. Его содержимое сразу отображается после всей песни в области разметки обычным текстом, без позиций для аккордов. Переносы и пустые строки примечаний сохраняются. Для изменения примечаний «Применить текст» не требуется; они записываются вместе с песней кнопкой «Сохранить».

TXT включает непустые примечания после песни, через пустую строку, без дорожек аккордов. Пустое поле или только пробельные символы ничего не добавляют в отображение и TXT. Старые песни без примечаний открываются с пустым полем.

### Клавиатура

| Действие | Результат |
| --- | --- |
| Tab / Shift+Tab в поле аккорда | Фиксирует аккорд и переходит к следующей / предыдущей позиции, включая другие строки. На границе песни фокус выходит из ввода. |
| Стрелки вниз / вверх | Открывают подсказки при наличии вариантов и выбирают вариант в списке. Прокручивается только список подсказок. |
| Enter в поле аккорда | Принимает явно выбранную стрелками подсказку или сохраняет ручной ввод, закрывает поле и возвращает фокус на ту же позицию без прокрутки. |
| Escape в поле аккорда | Сначала закрывает открытые подсказки; если они уже закрыты, фиксирует ввод, закрывает поле и возвращает фокус на ту же позицию. |
| Очистка поля | Удаляет аккорд при фиксации ввода. |
| Ctrl/Cmd+S | Сохраняет текущую песню в библиотеку выбранного режима. |

Потеря фокуса также фиксирует значение поля. Невалидное обозначение вызывает сообщение об ошибке; Enter, Tab и завершение через Escape не закрывают поле до исправления. После возврата на позицию доступна обычная навигация Tab.

### Выравнивание и TXT

В редакторе текст каждой непустой строки имеет минимальный левый отступ в два моноширинных символа относительно предстрочной позиции, даже если аккорда в ней нет. Длинный предстрочный аккорд увеличивает отступ при необходимости. Позиции над буквами и встроенное поле следуют за текстом.

Соседние длинные аккорды раздвигают отображаемые буквы, чтобы обозначения не перекрывались. Эти пробелы и двухсимвольный отступ не вставляются в исходный текст и не меняют сохранённые индексы букв.

«Экспорт TXT» скачивает название, автора отдельной строкой под названием (если заполнен), строки аккордов и текст песни с сохранением пустых строк между куплетами. Если над строкой текста нет аккордов, пустая строка аккордов не выводится. В TXT применяется раздвижение для длинных аккордов, но отдельный минимальный отступ в два символа относится только к редактору. Открывайте TXT моноширинным шрифтом. Экспорт не сохраняет изменения в JSON и не заменяет его для продолжения редактирования.

### Перенос привязок при изменении текста

«Применить текст» автоматически пересчитывает координаты аккордов на сохранившихся словах и надёжно сопоставленных буквах. Это позволяет исправлять небольшие опечатки, вставлять/удалять текст, разбивать и объединять строки, добавлять пустые строки. Полного сброса и подтверждения удаления всей разметки нет.

Перенос консервативен:

- Удалённая гласная теряет аккорд. Существенно заменённый фрагмент не получает привязку по случайно совпавшей букве.
- При повторяющихся словах сохраняются порядок и однозначные соответствия. Если нельзя надёжно определить нужный повтор, затронутые привязки снимаются.
- Небольшая правка внутри слова сопоставляется только в ограниченном случае: по одному слову с каждой стороны, не короче трёх символов, не более одного изменённого символа и не менее двух третей однозначно сохранившихся символов. Изменение границ слов при совпадении их объединённого текста обрабатывается для небольших групп.
- Краевые аккорды сохраняются, если сопоставленный контекст остаётся у соответствующего края новой строки. При разбиении строки начальный может следовать к первой части, конечный — к последней. Исчезнувшие при объединении границы теряют свои аккорды. Коллизии не перезаписывают другой аккорд.
- Объём сравнения ограничен. Большие фрагменты сопоставляются по уникальным словам и ограниченным локальным сравнениям; несопоставленные участки остаются без аккордов.

Снятые аккорды не хранятся отдельно: нужные вводятся заново обычным способом. Перенос меняет текущую песню в редакторе; файловая или браузерная библиотека обновляется только при явном сохранении.

## Данные и ограничения

В файловом режиме песня хранится в `songs/<UUID>.json`, в веб-режиме — в IndexedDB с теми же полями:

| Поле | Содержимое |
| --- | --- |
| `version` | Версия формата, сейчас `1`; это не история версий песни. |
| `id` | UUID v4, назначенный браузером или сервером. |
| `title` | Название; сервер обрезает пробелы по краям. |
| `author` | Автор, строка; может быть пустой. Старые файлы без этого поля открываются с пустым автором. |
| `text` | Исходный текст с переводами строк LF, без пробелов, добавленных раскладкой. |
| `notes` | Необязательный текст примечаний с переводами строк; сохраняется отдельно от текста и привязок аккордов. |
| `chords` | Объект вида `{"0:1":"Am"}`: ключ — `строка:индекс`, оба от нуля. Индекс — позиция Unicode-символа (`Array.from`), `-1` — перед строкой, длина строки — после неё. |
| `exportFile` | Имя TXT этой песни в файловом или браузерном хранилище экспорта; назначается при сохранении. Старые файлы могут не содержать поля. |
| `updatedAt` | Дата последнего сохранения в формате ISO. |

Оба режима проверяют название, допустимость позиций и обозначений. В файловом режиме сервер отвечает за запись в папки. Лимит тела запроса сохранения — 1 МиБ, включая JSON. JSON и TXT записываются через временные файлы и переименование; успешный ответ сохранения отправляется после записи обоих файлов. Библиотека читает JSON с именами UUID v4; посторонние и нечитаемые JSON пропускаются при построении списка. Запросы изменения с чужого Origin / cross-site отклоняются.

Для резервной копии скопируйте `songs/`. Учётных записей и облачного хранения нет. Параллельное редактирование одной песни в нескольких вкладках не поддерживается: последнее сохранение побеждает. История версий и транспонирование пока не реализованы — см. [TODO](TODO.md).

Раскладка рассчитана на русские и латинские буквы в моноширинном шрифте. Emoji, табуляция, комбинируемые и широкие символы могут визуально выравниваться иначе. Переносы текста textarea нормализуются браузером в LF. Автоматической отмены применения текста нет.

## Проверки

Для небраузерных тестов выполните `npm ci`: единственная тестовая зависимость — `fake-indexeddb`; в опубликованный сайт она не входит. Затем `npm run test:web` проверяет чистые функции, архив TXT и поведение браузерного хранилища без запуска браузера или сервера. Проверки IndexedDB используют тестовую реализацию API: сохранение, закрытие/повторное открытие, обновление автора и примечаний, конфликт импорта, атомарный откат и резервное копирование. Это не заменяет проверку в настоящем браузере, которую пользователь выполняет сам.

Полный набор: `npm test` или `node --test`. Серверный тест копирует проект во временный каталог и запускает отдельный слушатель на свободном порту; библиотеку пользователя он не меняет. Чистые функции можно проверить без сервера: `node --test test/core.test.mjs test/remap.test.mjs`.

Проверка синтаксиса интерфейсного кода: `node --check dist/app.js`. Команды здесь описывают доступные проверки, а не подтверждают их запуск после каждой правки. Браузерную проверку пользователь выполняет сам; постоянные условия работы приведены в [AGENTS.md](AGENTS.md).
